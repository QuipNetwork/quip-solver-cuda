# Acceptance run of the descent miner on the archived ice-charge models

This is the CU-7 (QUI-2242) acceptance record. On 2026-11-11, `quip-cuda-msa-descent` brought all 100 archived ice-charge models to or below `qpu80_pp`. Every job finished in 25.5 s or less, which is under 5 percent of the 600 s stall floor. Descent took a median of 0.27 percent of the kernel time. The host rescore matched on every model.

## Setup

| Item | Value |
|---|---|
| Binary | `quip-cuda-msa-descent`, release build of branch `feat/qui-2242-msa-descent` at `b88c12d` |
| Card | NVIDIA RTX A4000, physical GPU 0, driver 615.71.10 |
| Jobs | One `--solve` job at a time, 64 reads, 65,536 sweeps, one sweep per beta, production default beta range |
| Kernel seed | `protocol_seed(nonce)`, the research seed (`qpu-f17/generate.py:42-44`) |
| Policy | `msa-nat-loop/1`: natural greedy on every read, then loop descent on the lowest raw read |
| Tiles | Recovered from the graph (plain job, no family metadata) |
| Models and targets | `new-pow/targets-pp-100.json`, key `ice-charge`, read only |
| Tool | `tools/msa_descent_campaign.py --gpu 0`, with each job wrapped in `bench-evidence/cuda-sa-limitations/telemetry-run.sh` |
| Raw data | [`2026-11-11-cu7-ice-charge-a4000.jsonl`](2026-11-11-cu7-ice-charge-a4000.jsonl), one line per model |

## Results

| Measure | This run | Archived run (`round4-cuda-harness`) |
|---|---|---|
| Models at or below `qpu80_pp` after descent | 100 of 100 | 100 of 100 |
| Raw kernel best at or below `qpu80_pp` | 96 of 100 | 97 of 100 |
| Greedy best at or below `qpu80_pp` | 98 of 100 | 99 of 100 |
| Models where the loop result beats the greedy best | 90 | 85 |
| Mean margin below `qpu80_pp` | 2.012 units | 1.950 units |
| Smallest margin | 0.116 units | 0.142 units |
| Largest margin | 4.254 units | 5.150 units |
| Host rescore mismatches | 0 | 0 |

Against the archived final energies, this run is lower on 57 models and higher on 43 models. The mean difference is 0.063 units lower. The comparison is statistical, not per read. The production kernel differs from the archived build. The recovered tiles have the same set as the archived `tetrahedra` rows, but a different order. The loop seed is the job seed.

## Time per model

| Measure | Median | Lowest | Highest |
|---|---|---|---|
| Wall time per job (process start to exit) | 25.12 s | 24.96 s | 25.51 s |
| Kernel time | 22.88 s | — | 23.01 s |
| Descent time | 0.062 s | — | 0.358 s |
| Descent share of kernel time | 0.27 percent | — | — |

Nine of every ten models took 0.19 s of descent or less. Wall time includes process start, device setup, and the host scoring. The archived kernel median of 31 s comes from 33 or 34 jobs that shared the card, so the two kernel times are not directly comparable.

## Telemetry

The sampler took 2,294 one-second samples with the card fully busy over the 100 jobs. No sample showed an active software thermal slowdown, software power cap, or hardware slowdown. The median SM clock was 1,860 MHz (lowest 1,560 MHz, highest 1,905 MHz). The median temperature was 87 C, and the highest was 89 C. Per-job CSV files and counters are in `bench-evidence/cuda-sa-limitations/telemetry/cu7-*.{csv,counters}`.

## Reproduce

Run the campaign from the repository root on an idle card. It takes about 42 minutes.

```sh
cargo build --release --bin quip-cuda-msa-descent
/usr/bin/python3 -I -B tools/msa_descent_campaign.py --gpu 0 --out .tmp/cu7/campaign/ice-charge.jsonl
```
